# Challenge judging map

## WebMCP leverage

The product uses WebMCP as a stateful collaboration layer rather than a set of permanent CRUD shortcuts. Discovery is derived from lifecycle phase, room lens, permissions, domain policy, optimistic revisions, shared-authority availability, human-checkpoint state, and freeze state. The agent can construct a decision model, inspect exactly scoped source spans, run domain-permitted deterministic analysis, recompose the visible room, stage attributed review artifacts, and prepare local outputs. It cannot select arbitrary files, fetch a URL, inject presentation code, or cross a human-authority boundary.

Evidence to show:

- Real Chrome and Edge `getTools()` and `executeTool()` coverage in `tests/webmcp-browser.spec.mjs`.
- Compact capability replacement across Model, Analyze, Review, Prepare, and Frozen states.
- View-only composition with an unchanged byte-for-byte case, decision revision, and digest.
- Visible receipts and review artifacts settled before a mutating tool resolves.
- Cross-tab manual freeze and full cited human-resolution checkpoints through versioned shared governance; all mutation tools retire while a checkpoint is open.
- A visible session-only fallback that preserves the manual UI while disabling governed agent mutations.
- Reload-safe two-stage invocation handling: equal calls wait/replay, conflicts reject, expired pre-execution claims can be reclaimed, executing-without-result records become human-reconciled outcome uncertainty, and reset clears the journal plus its latest 100 receipts.
- Exact `caseId`/`jobId` source scoping before candidate and health-plan projection, with canonical sanitized evidence still readable after transient import cleanup.
- Candidate source inspection/search/span privacy with protected-value presence-oracle tests.
- Candidate evaluation and all seven prepared formats remain requirement-evidence-only, with no eligibility, score, rank, blocker, recommendation, or employment outcome.
- Health-plan identity and purpose policy uses the canonical `health-plan` pack and requires source-backed plan identity plus positively typed plan aspects.
- Bounded output retention keeps the latest 20 artifacts per case and surfaces cleanup failures rather than claiming silent durability.
- Ten model-facing selection and recovery tasks in `tests/fixtures/webmcp/evals.json`.

## Potential impact

Important decisions repeatedly fail in the gap between documents, spreadsheets, implicit assumptions, and opaque recommendations. SituationRoom creates one inspectable contract and evidence graph that can support procurement teams, hiring panels, consumers comparing health plans, and general high-consideration choices without pretending that every domain has the same policy or authority.

The valuable unit is not an AI answer. It is a cited, revisable decision record that survives human challenge, scenario analysis, export, and audit.

## Creativity and ambition

The page is a Living Caseboard that the agent recompiles around the current question. A causal investigation, aligned comparison, counterfactual fork, and stakeholder council are different spatial grammars with a recurring red evidence thread. The website becomes an authoritative visualization and computation surface while the agent becomes an intent interpreter and composition planner.

The universal kernel and allowlisted instrument grammar demonstrate a plausible new class of agent-native sites: the application does not expose a fixed dashboard for every task, and the agent does not generate arbitrary UI code.

## Claims to avoid

- Do not call the candidate room an automated hiring or ranking system.
- Do not imply that SituationRoom records a candidate outcome, even as a human action; the product exports only neutral requirement evidence for an external human process.
- Do not describe health-plan comparison as medical, insurance, or legal advice.
- Do not identify the health-plan pack as `health-plan-choice` or omit its plan-identity and source-evidence requirements.
- Do not claim every historical file format is parsed; distinguish native formats from recognized diagnostic-only formats.
- Do not claim WebMCP fetches URLs; agent intake is human-staged source IDs, with bounded inline text only for an existing authoritative case.
- Do not call print-ready HTML a binary PDF export.
- Do not report model-evaluation success rates until a model runner has actually executed the corpus.
- Do not say an agent commits purchases, sends messages, approves decisions, or performs external actions.
