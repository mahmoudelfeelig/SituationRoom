# Three-minute demonstration runbook

## One-sentence thesis

SituationRoom turns a person's intent and messy evidence into a purpose-built, auditable decision interface that an agent can continuously recompose, while deterministic rules and visible human authority remain fixed.

## Before recording

- Open a clean Chrome profile with WebMCP enabled and confirm the header reports contextual tools.
- Use **Reset demo** and verify four seeded rooms appear.
- Keep one mixed-format intake sample ready: a CSV or XLSX table, a PDF or DOCX narrative, and one deliberately untrusted instruction in a note.
- Use a 1440 x 1000 viewport, 100% zoom, and a pointer highlight that does not obscure source text.
- Record the real page and real agent interaction in one take. Do not substitute a mocked tool console or speed up state transitions beyond legibility.

## Screen story

| Time | What the judge sees and hears |
| --- | --- |
| 0:00–0:12 | Open on the procurement causal trace. State the thesis while the evidence-to-outcome red thread, Decision Firewall, authority, revisions, and contextual-tool count are already visible. |
| 0:12–0:34 | Ask: “Compare every vendor against the same mandatory gates and show what could reverse the recommendation.” The page visibly recompiles from a causal trace into an aligned matrix. Point out that the decision digest stayed fixed while the view revision changed. |
| 0:34–0:56 | Let the agent query evidence and challenge the recommendation. Open one exact source anchor and show the untrusted-source treatment, confidence, native locator, and audit receipt. |
| 0:56–1:18 | Ask for the smallest safe change that could make a blocked option viable. The page becomes a scenario fork; run the hypothetical and show that mandatory policy gates remain locked and the canonical revision does not change. |
| 1:18–1:38 | Make a visible human correction or stage a resolution request. Show that the agent-authored artifact is attributed, cannot impersonate a human, and changes what capabilities are discoverable in the Review phase. |
| 1:38–1:58 | Open **New decision**, stage the mixed files, and inspect the proposed contract. Show signature-aware format handling, a prompt-injection diagnostic, every inferred weight/range/gate/value/anchor, and the explicit human confirmation that commits a draft rather than silently activating it. |
| 1:58–2:18 | Rapidly switch to the blinded candidate and consumer health-plan rooms. Show protected candidate columns disappearing from source inspect/search/span results, then the provider/formulary evidence and consumer-only authority. This establishes that one kernel supports materially different governed decisions without flattening their policy boundaries. |
| 2:18–2:38 | Enter Prepare. Have WebMCP prepare a cited packet and information-request draft. Download one real JSON or DOCX artifact manually; stress that the agent cannot send, purchase, hire, underwrite, adjudicate, or approve. |
| 2:38–2:52 | Open the human approval preview. Show the exact digest binding and required confirmation, then close it without committing during the main take. Open the audit ledger and point to distinct decision, view, import, and tool receipts. |
| 2:52–2:59 | End on the four structural lenses and the claim: “The evidence stays fixed. The room rebuilds around your question.” |

## What must be visually undeniable

- The interface changes structure, not just text or color.
- A real `executeTool()` call settles visible page state before returning.
- Tool availability changes with Model, Analyze, Review, Prepare, and Frozen phases.
- A scenario and a composition change preserve the canonical decision digest.
- Imported instructions remain evidence text and cannot alter authority or capabilities.
- Candidate protected values remain absent from source inspection, search totals, span reads, and structured metadata.
- Agent artifacts are attributed and reviewable; consequential actions remain human-only.
- The same runtime handles procurement, candidate evidence, health-plan comparison, and a general imported choice.

## Contingency path

If the recording browser does not expose WebMCP, do not fake it. Show **Manual parity active**, complete the same workflow with the visible controls, then cut to the already-recorded real Chrome/Edge WebMCP test evidence. If an import source is malformed, keep the diagnostic on screen and use the seeded room rather than silently replacing the source.
